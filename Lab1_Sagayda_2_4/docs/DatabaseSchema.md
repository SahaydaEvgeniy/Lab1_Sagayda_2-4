# Схема локальної бази даних

Лабораторна робота 4, кроки 1–2. Файл `students.db3` створюється в
`FileSystem.Current.AppDataDirectory`. Версія схеми зберігається у `PRAGMA user_version`.

## Таблиця Students від версії 1

Таблиця `Students` відображає модель `Student` через атрибути sqlite-net-pcl.

| Поле таблиці | Властивість моделі | Дані |
| --- | --- | --- |
| `Id` | `Guid Id` | Сталий первинний ключ, зберігається як текстовий Guid |
| `FullName` | `string FullName` | ПІБ студента |
| `StudentGroup` | `string Group` | Група студента |
| `AverageScore` | `double AverageScore` | Середній бал у межах 0–5 |

`Id` не має автоінкремента: він створюється як Guid і залишається незмінним при
редагуванні, щоб зберігалася працездатність зовнішніх посилань.

`StudentRepository` реалізує `IStudentRepository`: `InitializeAsync`, `GetAllAsync`,
`GetByIdAsync`, `SaveAsync`, `DeleteAsync`. Кожна операція очікує ініціалізації.
Ініціалізацію захищено від одночасного виконання; створення таблиці та встановлення
версії виконуються в транзакції. База з новішою версією не понижується.

`SaveAsync` у транзакції визначає, чи існує Id, після чого вставляє або оновлює запис.
Репозиторій зареєстровано як Singleton у DI-контейнері. ViewModel не звертаються
безпосередньо до SQLiteAsyncConnection.

## Версія 2 та перенесення JSON

Додано таблицю `AppMetadata` з текстовими полями `Key` (первинний ключ) і `Value`.
Запис `LegacyJsonImported` позначає завершене одноразове перенесення `students.json`.

Під час переходу з версій 0 або 1 перевіряється весь JSON-список: повторні й порожні
Id та бали поза діапазоном 0–5 відхиляються. Вставляються тільки відсутні у SQLite
Id; існуючі записи не перезаписуються старими даними. Створення схеми, імпорт,
маркер і підвищення версії до 2 виконуються однією транзакцією. Помилка відкочує
всі зміни, після виправлення джерела операцію можна повторити.

Початковий JSON-файл залишається як резервна копія та більше не оновлюється.
Якщо JSON відсутній, міграція також позначається завершеною. Видалені з SQLite
студенти не імпортуються повторно після перезапуску.

## Використання застосунком

База ініціалізується при створенні вікна. У Debug Output з'являється
повідомлення `[SQLite] Ready` зі шляхом до файлу та версією схеми.
`StudentViewModel` асинхронно читає список і виконує додавання та видалення через
репозиторій; `StudentDetailViewModel` записує збережений бал до повернення на список.
Колекція в `AppStateService` є лише знімком для інтерфейсу та не викликає запис у БД.
Чернетка редагування залишається станом поточного сеансу.

Після помилки читання поточний список зберігається на екрані; після помилки запису
форма не очищується й запис не видаляється зі списку. Стан зайнятості блокує повторні
натискання, а кнопка «Оновити список» дозволяє повторити завантаження.
DeepLinkService отримує студента асинхронно за Id безпосередньо з репозиторію,
тому холодний запуск не залежить від того, чи встиг завантажитися список у пам'яті.
